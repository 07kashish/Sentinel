# Historical engineering artifacts

**Nothing in this directory is current truth.**

These are captured outputs from past engineering investigations — pytest runs,
bandit scans, ruff reports, junit XML, job manifests. They were committed at the
repository root, where they sat alongside the active documentation and were
indistinguishable from it.

That is the problem they are here to stop causing. A file called
`baseline_pytest.txt` at the root of a security product reads like the current
test baseline. It is not: it is a snapshot of one run, on one machine, at one
commit, none of which it records.

## Where current truth lives

| Question | Source |
|---|---|
| Does the build pass? | CI on the commit in question |
| What is the release status? | `release/readiness.json` — generated, never hand-edited |
| What does the detector actually score? | `evaluation/metrics.json`, regenerated by the metrics gate |
| What are the known limitations? | `docs/PRODUCTION_READINESS_REPORT.md` and the per-phase documents |

## Why they were kept rather than deleted

Deleting them would lose the record of what was measured and when, which is
occasionally the thing you need when a regression turns out to be three months
old. They are moved, not destroyed — and moving them is what makes the active
documentation unambiguous.

If you are looking for the state of the product, do not read anything in this
directory.
