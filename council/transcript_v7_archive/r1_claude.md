## Strengths
- **Fail-closed provenance genuinely holds.** `verify_package` refuses without an out-of-band `trusted_signer` (`app/attestation/verify_package.py:272-280`), never falls back to the package's own `signer_address` (`:300`), and requires a signature recovering to the trusted address. To forge a `True` you need the signer's private key — I could not construct a bypass. Caveat: this rests entirely on `recover_address`/`sign_digest` (`app/attestation/signing.py:33`), which the brief flags as **unaudited**; the whole guarantee is only as sound as that primitive.
- **Deterministic authority is real, not asserted.** Priority is `priority_for_severity(severity)`, a pure function (`api/pipeline.py:218`); the LLM's opinion is recorded as `advisory_*` (`:127-133`) and its failure is non-fatal (`:117`). This closes the "model in the control path" class rather than relocating it.
- **The mutation harness is not theatre.** It loads a mutated module and *requires* the probe to raise, with an explicit `MUTATION SURVIVED` failure and an anchor-missing guard so a moved guard fails loud rather than silently testing nothing (`tests/mutation_support.py:53-60, 94-100`). This is the correct answer to the prior "substring on `inspect.getsource`" theatre.
- **Shared rate limiter is actually wired**, not just written — `_enforce_rate_limit` calls `ratelimit.check` inside `require_role` (`api/rbac.py:168,203`), which is applied across routes. Contrast OIDC's prior "imported by nobody" defect; this one is reachable.
- **Redaction preserves the chain without a new forge path.** Ledger holds only `entry_hash`; body lives in mutable `evidence.content_json` (`app/attestation/redaction.py:13-21`). A redacted package reports `REDACTED` distinctly and still fails closed (`verify_package.py:218-229`).

## Weaknesses & architectural issues

- **The execution fence relocated the failure, it did not close it (headline finding).** | Evidence: `api/pipeline.py:264-320` performs `still_owned()` then the append-only/external write — `evidence_ledger.record` (`:265`), `db.save_report` (`:295`), `publish_attestation` (`:307`) — *before* the fenced transition that records it. `still_owned()` is `assert_execution`, a read on a **separate connection** whose own docstring admits it "narrows the window rather than closing it" (`app/core/repository.py:250-262`). | Risk: a worker reclaimed between `still_owned()` and the write produces a **duplicate append-only ledger leaf and/or a duplicate on-chain anchor that cannot be withdrawn**; only the subsequent transition raises `FenceLost`. This is the sixth instance of the codebase's signature pattern — the guard moved one layer up (from queue row → transition write → non-transactional side effect) rather than closing. | Fix: make the side effect and the state transition that asserts it share one row-locked transaction (write evidence/ledger *inside* the fenced transition, or use an idempotency key on `(incident_id, execution_epoch)` for ledger append and anchor publish so a duplicate is unrepresentable, not merely unlikely). | Effort: 2–3 days. | Priority: **High**.
- **Cross-source detection is effectively non-functional and shipped anyway.** | Evidence: `evaluation/results/leave_one_source_out.json` — MultiJail fold recall 0.0273, fnr 0.9727. | Risk: the product's stated value ("see/audit agents before risk") rests on detection it does not have; a buyer's first red-team makes this visible. | Fix: this is a research problem, not a patch — narrow the claim to "deterministic policy engine + BYO-detector" and stop implying detection. | Effort: framing = 1 day; real detection = months + data. | Priority: **High** (honesty), Critical (business).
- **RLS defaults OFF and is a foot-gun when enabled.** | Evidence: brief §8 + policy `tenant_id = current_setting('sentinel.tenant_id', true)`; unset context is NULL → every query returns zero rows unless a tenant contextvar is threaded through every transaction. | Risk: the isolation guarantee marketed to enterprises is inert by default and dangerous to flip on. | Fix: thread `SET LOCAL sentinel.tenant_id` into `db._connect()` transaction scope and default RLS on in the Postgres profile. | Effort: 3–5 days. | Priority: **High**.
- **SQLite-first persistence with a DB round-trip per rate-limit check.** | Evidence: `app/core/ratelimit.py:56-87` opens a `BEGIN IMMEDIATE` transaction per request; `db._connect()` is the hot path everywhere. | Risk: the limiter that exists to shape load becomes the bottleneck under load. | Fix: Redis token bucket (or Postgres advisory locks) for the limiter; treat SQLite as dev-only. | Effort: 1 week. | Priority: **Medium**.

## Gap analysis
Real unsolved pains: (1) **auditable non-repudiation of agent actions** for regulated buyers — Sentinel can credibly address this; the ledger design is sound. (2) **Instrumentation tax** — manual per-call SDK wiring is the adoption killer, and no OTel auto-instrumentation exists (brief §8); this is fatal to bottom-up adoption. (3) **Detection of goal-hijack/tool-misuse (ASI01/02)** — Sentinel *cannot* credibly close this; its own numbers say so. (4) **Stranded-buyer opportunity** from consolidation (brief §5) — real, but requires a product enterprises trust, which a pre-production tool is not.

## Missing / critical features
SOC2/ISO artifacts; OTel/framework auto-instrumentation (LangChain/LlamaIndex/MCP hooks); a real multi-tenant console (current UX is one static HTML file); SSO/SCIM beyond raw OIDC; audit-log export to SIEM; per-tenant policy authoring UI; alerting/notification integrations; a signed-key management story (KMS/HSM, not an env var — `SENTINEL_LEDGER_SIGNING_KEY`); DR/backup runbook for the ledger.

## Feature discovery — non-obvious features
1. **Portable Agent Evidence Standard.** Problem: every vendor's audit log is a silo. Impact: makes Sentinel the *format*, not the tool. Complexity: medium. Design: publish the evidence-package schema + `verify_package` as an open spec/CLI; anchor commitments hourly, not per-event. AI need: none. Defensibility: standards ownership + network effect.
2. **Kill-switch attestation.** Problem: 55–63% of orgs have no kill switch (brief §1). Design: bind a signed "agent halted at epoch N" record into the same ledger. AI need: none. Defensibility: ties the compliance story to enforcement.
3. **Differential replay verifier.** Problem: proving an agent's action matched approved policy at decision time. Design: sign the (policy_version, decision) tuple; auditor replays offline. Reuses existing signing. Defensibility: patent-adjacent, no competitor offers cryptographic decision-provenance.
4. **BYO-detector marketplace.** The registry already exists (`app/detection/registry.py`); expose it as a plug-in surface so Sentinel monetizes *others'* detection while owning attestation.

## Scalability & performance concerns
SQLite default (`db._connect()` everywhere); synchronous transactional DB hit per rate-limit check (`ratelimit.py:57`); per-event ledger append with head read inside the insert transaction (`ledger.py:60`) serializes writes per tenant; on-chain anchoring is orders of magnitude slower than a DB (brief §7) — correctly optional, but the "millions of events/sec" story is impossible on-chain and unproven off it. No Kubernetes run has ever happened (brief §8). Bottleneck order to millions of users: limiter → per-tenant ledger serialization → Postgres write throughput.
