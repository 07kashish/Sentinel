## Final position (one paragraph)
Sentinel SOC is a well-wired hackathon artifact with a handful of genuinely correct primitives — a clean event schema (`api/schemas.py:82-120`), a real priority queue (`app/queue/priority_queue.py:9-37`), deterministic Keccak evidence hashing (`agents/evidence_agent.py:15-32`), three agents that make real `gpt-4o` calls, a functioning `web3.py` broadcast to Base Sepolia (`agents/attestation_agent.py:64-103`), and a robust deterministic report generator (`agents/reporting_agent.py`). Everything load-bearing for the *security* claim is theater: live detection is substring matching (`app/monitoring/rules.py:12-14`), remediation only prints (`app/response/mitigation.py:7-23`), threat intel is hardcoded fixtures, metrics grade a fixed 7/3 demo split (`evaluation/metrics.py:64-77`), all state dies on restart (`api/store.py:14`), and the ingestion API fails open with no key and leaves `/analyze`, `/ingest/*`, and `/simulate-attack` unauthenticated (`api/main.py:97-103`, `:685-714`). The disqualifying find, which no round-1 seat caught: the attestation-mode label is derived from the private key alone (`main.py:149-151`) while actual on-chain writes need both key and contract address (`attestation_agent.py:29-32`), so an incident can be stamped `attestation_mode="REAL"` with nothing on-chain — and a failed chain write still yields a `status="complete"` incident (`main.py:236` vs `:291-295`). A trust layer that lies about its own trust is not a foundation; it is a rewrite waiting to happen.

## The 90-day plan — 5 things in priority order
1. **Fix the trust-integrity lies, then delete the fake surfaces.** Label attestation from the actual publish result (`attestation.attestation_mode`), not the key check; make a failed chain write produce a failed incident; remove the dead monitor, the printf mitigation, and the rigged metrics. *Why:* you cannot demo or sell a "trust layer" that fabricates trust state — this is credibility-negative before it's feature-negative. *Effort:* ~1 week; mostly deletion and one label fix.
2. **Persist everything and lock the boundary.** Postgres for incidents/evidence/preimages; enforce API keys on every ingestion route; refuse startup with no key instead of failing open; scope CORS. *Why:* durable, searchable audit logs are the minimum viable claim for observe-mode, and fail-open auth is disqualifying for a security tool. *Effort:* 2-3 weeks.
3. **Replace substring detection with a measured classifier on real traffic.** Ship a small labeled corpus (not `demo_events.py`), report precision/recall/FP-rate honestly, and start with prompt-injection + tool-misuse (ASI01/ASI02) done well rather than ten done nominally. *Why:* the buying signal (brief §4) is "see/test/audit agents before risk," and that requires numbers you didn't author. *Effort:* 3-4 weeks, ongoing.
4. **Add agent identity binding.** Move from caller-asserted `agentId` strings to a stable per-agent credential (API-key-scoped at minimum, PKI-aspirational), and make on-chain identity deterministic per agent rather than a fresh random address (`attestation_agent.py:72-77`). *Why:* ASI03 is the brief's most-cited structural gap and the thing that makes attestation meaningful. *Effort:* 2 weeks for the durable-key version.
5. **Rebuild attestation as hybrid anchoring, off the demo headline.** Local Merkle-tree over incidents, periodic root commitment to a real L2 (not testnet), and drop blockchain from the top-line pitch. *Why:* per-event testnet writes read as unserious to a CISO and don't scale; hybrid anchoring is the mainstream pattern (brief §7). *Effort:* 3-4 weeks.

## What would have to be true for this to be a $100M company
Three things simultaneously. (1) **A real detection edge**, not rules — measured precision/recall on adversarial agent traffic that beats a Lakera free tier for the specific case of *tool-call and inter-agent* abuse (ASI02/ASI07), where the incumbents are weakest because they came from the prompt-firewall side. (2) **A distribution wedge into the stranded mid-market** — the 5-50-engineer AI-native teams that Palo Alto's quote-based motion won't service, reached via a genuinely drop-in SDK with self-serve onboarding, so CAC is near-zero. (3) **A data flywheel** — cross-tenant (privacy-preserving) attack telemetry that makes the detector improve with each customer, which is the only durable moat in a category where rules are copyable in an afternoon. The on-chain piece is at best a compliance garnish, never the wedge. Without all three, this asymptotes to a lifestyle pilot business, not a venture outcome.
