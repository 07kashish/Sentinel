Start a controlled pilot

Discover known AI apps, connect one selected tool, observe its traffic, then test approval and enforcement in a disposable resource. Discovering an app does not give Sentinel access to it.

    1. Discover local AI apps with permission

    The companion checks only the presence of known AI configuration files, macOS app bundles and command names. The HTML file it writes is a readable copy you can open locally. It does not read their contents, existing keys, chats, browser data or process memory. Applications are checked on macOS and Windows, commands on macOS, Linux and Windows; custom installations and browser-only AI can be missed.

    Requires Python 3.9 or newer; or use the Sentinel AI Scan desktop app, which needs nothing installed. Inspect the downloaded source, then run these commands from its folder. No administrator permission is needed.

    python3 sentinel-discover.py --explain
python3 sentinel-discover.py --consent --all --output sentinel-device.json --html sentinel-device.html

    Review the local report before importing. The report contains a random device ID, OS family, timestamp, selected permissions and presence results. It sends nothing automatically. Reports are retained until an administrator deletes or replaces them.

    2. Review discovered software

    Self-reported configuration or installation presence. Activity, agent identity and enforcement are not established by this list. Delete removes the stored report; it does not uninstall software.

    3. Connect a selected tool

    Ask your administrator to enroll an agent and a reviewed MCP server, enable the MCP proxy, and issue a separate agent credential. Route that server through Sentinel using the bundled sentinel-mcp-stdio bridge or your host's remote MCP configuration. Keep all other tools marked outside enforcement coverage. Test refusal during a Sentinel outage.

    Gemini CLI and Antigravity are separate clients. Installing them does not connect them to Sentinel. Their model API keys stay with the client; never use them as Sentinel operator tokens.

    4. Confirm the investigation advisor

    The deterministic policy engine makes decisions. An optional model adds unverified investigation notes and cannot approve or execute changes. To bring a provider API key, the administrator configures an HTTPS chat-completions-compatible endpoint, model and token in the deployment's managed secrets/configuration. The browser never collects provider keys. A Gemini CLI tool connection does not configure this advisor.

    5. Run the pilot acceptance journey

    1. Use a separate tenant, named operator accounts and a disposable resource.
    2. Confirm HTTPS, viewer restrictions and tenant isolation before adding private credentials.
    3. Observe one tool and record routed traffic plus known bypass paths.
    4. Request a constrained change; confirm it cannot run before approval.
    5. Approve, execute, inspect the receipt and verify it independently.
    6. Try replay, substituted arguments, denied scope and dependency outage; count target-side effects.
    7. Reconcile uncertain outcomes and export evidence to the pilot's SIEM.
    8. Record onboarding time, approval time, interruptions and support effort. Expand only after acceptance.
